# 并发支持说明

## 📋 概述

本文档说明 TSC Ansible MCP 服务对并发会话的支持情况。

## ✅ 并发支持状态

**支持 2-5 个并发会话** - 已通过测试验证

## 🔧 已修复的并发问题

### 1. Inventory 文件竞争 ✅

**问题描述：**
- 多个会话同时写入 `inventory.yml` 会导致数据丢失
- 最后一个写入的会话会覆盖其他会话的修改

**解决方案：**
```python
# 使用文件锁（fcntl）确保线程安全
fcntl.flock(f.fileno(), fcntl.LOCK_EX | fcntl.LOCK_NB)
```

**改进内容：**
- ✅ 添加文件锁机制（排他锁 + 非阻塞）
- ✅ 实现重试机制（最多3次）
- ✅ 添加超时处理
- ✅ 详细的日志记录

### 2. SQLite 并发限制 ✅

**问题描述：**
- SQLite 默认不支持高并发写入
- 可能出现 `database is locked` 错误

**解决方案：**
```python
# 优化 SQLite 配置
self.engine = create_engine(
    db_url,
    connect_args={
        "check_same_thread": False,  # 允许多线程访问
        "timeout": 30,  # 增加超时时间
    },
    pool_pre_ping=True,  # 检查连接有效性
    pool_recycle=3600,  # 定期回收连接
)
```

**改进内容：**
- ✅ 允许多线程访问
- ✅ 增加超时时间（30秒）
- ✅ 连接池健康检查
- ✅ 定期回收连接（每小时）

## ⚠️ 注意事项

### 1. Inventory 文件
- 虽然支持并发，但频繁的并发写入会影响性能
- 建议避免在短时间内大量并发更新同一主机

### 2. SQLite 限制
- SQLite 适合中小规模并发（<10个并发写入）
- 如需更高并发，建议迁移到 PostgreSQL 或 MySQL

### 3. 资源消耗
- 每个并发会话会占用独立的资源
- 建议监控内存和 CPU 使用情况

## 🔍 故障排查

### 问题 1: Inventory 文件锁定超时

**症状：**
```
ERROR - 保存 Inventory 失败（文件锁超时）
```

**原因：**
- 并发写入过多
- 文件锁等待时间过长

**解决方法：**
1. 减少并发会话数量
2. 增加 `_lock_timeout` 值
3. 检查是否有死锁进程

### 问题 2: 数据库锁定

**症状：**
```
ERROR - database is locked
```

**原因：**
- SQLite 并发写入超过限制
- 长时间运行的事务

**解决方法：**
1. 检查是否有长时间运行的任务
2. 重启服务释放连接
3. 考虑迁移到 PostgreSQL
